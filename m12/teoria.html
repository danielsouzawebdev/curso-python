Projeto Integrador — Teoria

Projeto Integrador — Sistema de Gestão de Chamados

O projeto reúne os conceitos do curso em uma aplicação desktop com persistência.

Requisitos

IDRequisito
RF01Cadastrar usuários.
RF02Cadastrar categorias.
RF03Abrir chamado com título, descrição, prioridade e categoria.
RF04Alterar status respeitando regras.
RF05Pesquisar e filtrar chamados.
RF06Persistir em SQLite.
RF07Interface Tkinter.
RF08Exportar relatório CSV/JSON.
RF09Registrar logs.
RF10Testar regras principais.

Arquitetura sugerida

projeto/
├── app.py
├── dominio/
│   ├── chamado.py
│   └── usuario.py
├── dados/
│   ├── conexao.py
│   └── chamado_repo.py
├── servicos/
│   └── chamado_service.py
├── ui/
│   └── main_window.py
├── tests/
├── requirements.txt
└── README.md

Critério principal

O projeto deve demonstrar separação de responsabilidades. A UI não deve decidir regra de negócio e o repositório não deve controlar widgets.
